# Design note: timeline v1, edit ops and renderer (P3)

> Status: **accepted for P3** · 2026-10-16 · Applies [D-02](../05-decisions.md#d-02-edit-representation-declarative-timeline-json--deterministic-renderer), [D-03](../05-decisions.md#d-03-music-cue-only-by-default) and [D-24](../05-decisions.md#d-24-public-ids-are-typeids-over-uuidv7). The Go types are written by hand rather than generated: generated Go from JSON Schema is poor for tagged unions. Schema validation in Go uses `github.com/santhosh-tekuri/jsonschema/v6` (Apache-2.0, pure Go).

## 2. The spec

The shape in architecture §6 stands. These are the rules it leaves open.

**Top level.** `schema` is the constant `contentfabrique.timeline/v1`. `output` has `format` (`9:16`, `1:1`, `4:5` or `16:9`, [D-25](../05-decisions.md#d-25-output-formats-916-11-45-and-169-per-project)), `width` and `height` (which must equal the format's size: 1080×1920, 1080×1080, 1080×1350 or 1920×1080), `fps` (one of 24, 25, 30, 60) and `background` (`#rrggbb`). `tracks` and `markers` are arrays, and `meta` is an optional object with `idea_id` and `concept_id`. Unknown properties are rejected everywhere (`additionalProperties: false`), so a typo from the agent fails loudly.

**Tracks.** Exactly one `video` track, and its id is `main`. At most one `text` track, at most one `captions` track and at most one `audio` track. Overlay video tracks come later. The schema enforces the counts with `contains`/`maxContains`, and tells the track types apart by `type`.

**Required fields and defaults.** The schema requires what has no sensible default: on a video item `id`, `asset_id`, `source` and `at_ms`; on a text item `id`, `at_ms`, `duration_ms`, `text` and `style`; on a captions track `from`, `style` and `enabled`; on every audio item its kind's fields, `at_ms`, `source_offset_ms` and `export`; on a marker `at_ms` and `kind`. Everything else is optional and the compiler applies the default named in the tables: `speed` 1, `reframe` as `cover` at focus 0.5/0.5 and zoom 1, `look` none, `transition_in` a cut, `audio` silent, `animation` none, `strength` 1. An empty `main` track is structurally valid and fails the duration check. Every time field is at most 86 400 000 ms (24 hours). Go validation sums times as `int64`, so sums of several fields can't overflow.

**IDs.**
- Item and track ids match `^[a-z][a-z0-9_]{0,31}$` and are unique across the whole spec. The agent and the ops name items by these ids.
- References to platform objects (`asset_id`, `moment_id`, `trend_id`, `idea_id`, `concept_id`, `license_id`) are TypeIDs ([D-24](../05-decisions.md#d-24-public-ids-are-typeids-over-uuidv7)) with a fixed prefix per field: `ast`, `mom`, `trd`, `ide`, `con`, `lic`.

**Time.** Every time is an integer number of milliseconds ≥ 0. No floats.

**Video items** (`main`):

| Field | Rule |
|---|---|
| `source.in_ms`, `source.out_ms` | `0 ≤ in < out ≤ asset duration` |
| `at_ms` | See contiguity below |
| `speed` | 0.25 to 4.0, default 1.0 |
| `reframe.mode` | `cover`, `contain` or `blur_fill`; `focus.x`, `focus.y` in [0, 1] (default 0.5); `zoom` 1.0 to 3.0 |
| `look.preset` | `none`, `punchy`, `warm`, `cool`, `bw`, `matte` |
| `transition_in` | `{ "type": "cut" }` or `{ "type": "crossfade" \| "dip_to_black" \| "whip", "duration_ms": 100–1000 }`. The first item must be a cut (or have none); the schema checks that with a one-element `prefixItems` |
| `audio` | `use_source` (default false) and `gain_db` (−30 to +6) |
| `moment_id`, `why` | Optional. `why` is at most 280 characters and is never rendered |

An item's **output duration** is `floor((out_ms − in_ms) / speed + 0.5)`: round half up, which for these non-negative values is round half away from zero (Go `math.Floor(x + 0.5)`; `math.Round` agrees). With a speed that is a power of two the quotient is exact, so the .5 case is exact: 3001 ms at speed 2 is 1501 ms.

**Contiguity on `main`.**
- The items are sorted by `at_ms`, the first starts at 0, and each next item starts at the previous item's end minus its own transition duration.
- Gaps are errors, and so are overlaps that no transition explains.
- `at_ms` is redundant with the durations on purpose: it keeps diffs readable and lets the UI place items without computing anything. The ops keep it consistent (§4).

**Text items** (`text` track): `at_ms`, `duration_ms` (≥ 300), `text` (1 to 120 characters, at most 3 lines; the schema counts lines by `\n` with a `pattern` and characters as code points, so Go must count runes, not bytes. Control characters other than `\n` — including `\r`, tab and NUL — and U+2028 and U+2029 are rejected; every other character is allowed, and §5 says how P3-04 keeps them from being read as markup), `style` (an id from the style registry, §5), `anchor` (`upper_third`, `center`, `lower_third`) or `position` `{x, y}` in [0, 1] (exactly one of the two), and `animation` (`none`, `pop_in`, `fade`, `typewriter`, `slide_up`).

**Captions track:** `from: "transcript"`, `style` (`word_highlight` or `chunk`), `enabled`, `uppercase` (default true) and `max_words` (1 to 4, default 2).

**Audio items:** `export` is required on every item, and each kind's variant fixes it (`cue_only` for `trend_sound`, `licensed` for the other two).

| `kind` | Fields | `export` |
|---|---|---|
| `trend_sound` | `trend_id`, `source_offset_ms` | Must be `cue_only`. The schema enforces it twice: the variant's `const`, and an `if`/`then` on `kind` whose error points straight at `/export` |
| `licensed_track` | `asset_id`, `license_id`, `source_offset_ms` | `licensed` |
| `creator_audio` | `asset_id`, `source_offset_ms` (the creator's own upload, with a rights attestation) | `licensed` |

Every audio item has `at_ms`, an optional `duration_ms` (default: to the end of the timeline), `gain_db` (−30 to +6) and an optional `fade_in_ms` and `fade_out_ms`. Audio items may overlap, because they are mixed. A sound with no `duration_ms` plays to the end of the timeline, so its effective duration is the total duration minus `at_ms`.

**Markers:** `at_ms`, `kind` (`beat`, `downbeat`, `drop`, `section`) and `strength` in [0, 1].

## 3. Validation

`timeline.Validate(spec []byte, assets AssetCatalog) Result` runs in two layers:

1. **Structure.** The JSON Schema rejects wrong types, ranges and enums, unknown fields, the format/size pairing, track counts, text with both or neither of `anchor` and `position`, a first clip that is not a cut, text over 3 lines and the `trend_sound` export rule. Track, audio-item and transition types are `oneOf` unions, so one mistake yields errors for every branch. The Go layer reports only the branch whose discriminator (`type`, `kind`) matches, so the agent sees one message per problem.
2. **Semantics.** Go checks what the schema can't express: unique ids, contiguity (including the first item starting at 0), `0 ≤ in_ms < out_ms ≤` the asset's duration (from the catalog), minimum shot length (an output duration ≥ 300 ms), total duration from 1 s to 180 s, every text item, audio item and marker inside the total duration, text inside the safe zone (§5), transitions shorter than both items they join, a transition on the first clip in time (`first_transition`), assets of the right kind (`wrong_asset_kind`), audio ranges and fades (below) and licensed audio (below). Contiguity is checked against the formula above, whatever the transition lengths. A clip with `in_ms ≥ out_ms` raises `source_out_of_range` only and is left out of the length, contiguity and total-duration checks. Each of these checks is a separate code, and the fixtures raise exactly one code each.

**Audio checks.**
- `source_out_of_range` also covers audio: `source_offset_ms` + the effective duration must be within the asset's duration. `trend_sound` has no asset in the catalog, so it has no range.
- `outside_timeline` covers audio: `at_ms` below the total duration, and `at_ms + duration_ms` at most the total duration.
- `fade_too_long`: `fade_in_ms + fade_out_ms` at most the effective duration.
- `wrong_asset_kind`: a `main` clip needs a catalog asset of kind `video`; a `licensed_track` or `creator_audio` needs one of kind `audio`. The rights of a wrong-kind audio asset are not checked, so the item raises this code only. An unknown asset raises `unknown_asset` instead.
- `unlicensed_audio` ([D-03](../05-decisions.md#d-03-music-cue-only-by-default)): a `licensed_track` needs a catalog asset of kind `audio` whose rights are `licensed` (a licence record exists); a `creator_audio` needs a catalog asset whose rights are `attested` (the creator's rights attestation). An asset the catalog doesn't know raises `unknown_asset` instead. `trend_sound` is `cue_only` and never needs a licence.

`Result` holds `[]Issue{Code, Path, Message, Severity}`:
- `Path` is a JSON Pointer into the spec, such as `/tracks/0/items/3/source/out_ms`.
- `Severity` is `error` or `warning`. Only errors block a version.
- `Code` comes from a closed, documented list, such as `schema`, `duplicate_id`, `gap`, `overlap`, `source_out_of_range`, `shot_too_short`, `duration_out_of_range`, `outside_timeline`, `unsafe_text`, `unknown_asset`, `transition_too_long`, `unlicensed_audio`, `fade_too_long`, `wrong_asset_kind` and `first_transition`; P3-04 adds `unsupported_character` (a character the style's font has no glyph for) and `text_overlaps_captions` (a text item over the caption band of an enabled captions track), see section 5. `first_transition` is a `transition_in` other than a cut on the first clip **in time order**: the schema only checks the first clip of the array, and an array that is out of order but contiguous by time can put another clip first. A style id that the style registry (section 5) doesn't know is `unknown_style`, an **error** since P3-04 (it was a warning while the registry was a stub); the message lists the ids that exist. The editor agent sees the codes and messages, so they are written for a model to act on: "item c3 ends at 5400 ms but asset ast_… is 5100 ms long".

`AssetCatalog` is an interface with one method, `Lookup(assetID) (Asset, bool)`, so each item costs one lookup. `Asset` is `{DurationMs int64, Kind AssetKind, Rights Rights}`, where `AssetKind` is `video` or `audio` and `Rights` is `licensed`, `attested` or `none`. Tests use an in-memory map loaded from `fixtures/assets.json`.

## 4. Edit ops and versions (P3-02)

- **Ops are JSON objects** with an `op` field: `add_clip`, `remove_item`, `move_item`, `trim_item`, `replace_source`, `set_speed`, `set_reframe`, `add_text`, `update_text`, `remove_text`, `set_transition`, `set_sound`, `remove_sound`, `snap_cuts_to_beats`, `set_look`, `set_captions` and `set_clip_audio`. Each op has its own definition in `packages/schemas/timeline/ops.v1.schema.json` (a single op is the root, a batch is `$defs/opBatch`, 1 to 100 ops), with titles and descriptions written as tool documentation: the editor agent's `edit_timeline` tool takes a batch of ops, so these schemas become its tool contract in P4-02. The schema is closed and copies the shared definitions of `v1.schema.json` (a test keeps them equal); the Go copy is embedded by `internal/timeline/ops` (`go generate`, CI copy check). Effect presets (D-26) arrive as further additive ops.
- **What the ops take.** Clips are named by id and placed by `index` (the position the clip will have, 0 is the start) or `after_id`; text items and sounds by an absolute `at_ms`. `trim_item` takes absolute values: `in_ms`/`out_ms` for a clip, `duration_ms` for text and sounds. `move_item` takes exactly one of `at_ms`, `index` and `after_id`. `set_reframe` and `set_sound` replace the whole reframe or sound (what they leave out goes back to its default); `update_text`, `set_captions` and `set_clip_audio` change only the fields given; `set_look` without an id applies to every clip. `set_transition` takes `type` and, except for a cut, `duration_ms`. `set_sound` derives `export` from `kind` (the agent cannot get it wrong). `set_sound` with the id of an existing sound replaces it in place; `set_captions` and the first `add_text`/`set_sound` create their track (ids `captions`, `text`, `sound`, or `<name>_2` if the id is taken). `snap_cuts_to_beats` takes a `grid` (constant `{bpm, first_beat_ms, beats_per_bar?, downbeat_offset?}` or a list `{beats_ms, downbeats_ms?, beats_per_bar?}`), an optional `sound_id` and `options` (`max_shift_ms`, `max_shift_beats`, `prefer_downbeats`, `min_shot_ms`, `write_markers`).
- **`Apply(spec, ops, catalog) (spec', Result)` is atomic and pure.** `internal/timeline/ops`. It applies the whole batch to a copy, re-runs `Validate`, and returns either the new spec or the original spec, unchanged, with the issues. `ops.ParseBatch` decodes the agent's JSON strictly: each op is checked against its own definition of the schema (so a field written in another case, an unknown field or a value out of range is an issue that names the field) and then decoded into its Go type.
- **Issues name the op.** `Result.Issues` holds `{op_index, op, code, field, path, message, severity}`. An op that cannot be applied (`unknown_item`, `wrong_item_kind`, `id_taken`, `bad_position`, `bad_argument`, `invalid_op`, `unknown_op`, `batch_size`) stops the batch at that op; the ops after it are not looked at, since they would mostly fail for the same reason. Problems in the resulting spec are all reported at once, with the codes of section 3; each is blamed on the last op that touched the item its path points into, and a problem with something no op touched (a text item that now runs past the end, the total duration) on the last op that changed the length of `main`. Warnings (`unknown_style`, `cut_not_snapped`, `no_cuts`) never block. `Result.Created` lists the ids that new items got.
- **The ops ripple on `main`.** A trim, insert, removal, move, speed or transition change recomputes `at_ms` for every later main item (`at_ms = previous end − own transition`). Text and audio items keep their absolute times. A text item that now overruns the end triggers an `outside_timeline` error, so the agent fixes it on purpose, in the same batch if it likes. `main` is kept in time order (an out-of-order array that is contiguous by time is sorted first). A clip that plays nothing (`in_ms` not below `out_ms`) takes no time, as in the validator. A clip that becomes first by a `remove_item` or `move_item` loses a `transition_in`; a `transition_in` that the agent sets on the first clip is an error.
- **New item ids.** `add_*` ops and `set_sound` accept an optional `id`. Without one, the engine assigns `c<n>`, `t<n>` or `s<n>`: one more than the highest number in use for that prefix (counting the ids given explicitly, and the ones removed earlier in the same batch, so an id is never handed out twice in a batch). Assignment is deterministic, which keeps replays and golden tests stable.
- **Versions are immutable.** `ops.Version{Number, Parent, Spec, Ops, Diff, AuthorKind, AuthorID, Summary}` with `ops.NewVersion(parent, ops, author, catalog)`; it returns no version when the batch fails or changes nothing (a `no_change` warning). The `timeline_versions` table (migration 00009, next to `projects` and `project_assets`) stores `version`, `parent_version`, `spec`, the applied `ops`, `diff`, `summary`, `author_kind` (`agent` or `user`) and `author_id`, plus a `tl_` id. It is append-only: the app role has INSERT and SELECT only, and a trigger refuses UPDATE for every role. `POST /v1/projects/{id}/timelines` writes a version: it takes `base_version` (0 for a project without a timeline), locks the project, answers 409 `version_conflict` when `base_version` is not the current version, and applies the ops against a catalog of the project's own ready footage.
- **The diff is an RFC 6902 JSON Patch** from the parent to the child (`internal/timeline/diff`: `Diff`, `Specs`, `ApplyPatch`, `ApplySpec`, `Summarize`). Objects are diffed key by key; arrays whose elements all have a unique string `id` (the tracks, and the items of a track) are diffed by id, so a reorder is a `move` per misplaced item (the items that keep their relative order stay) and a trim is one `replace`; any other array is diffed by index. The property tests check that `ApplyPatch(parent, Diff(parent, child)) == child` for every applied batch, that a random op sequence never yields a spec that fails validation (it either applies cleanly or returns issues and leaves the spec byte-identical), that ids are unique and `main` is contiguous. `Summarize(parent, diff)` gives a line per change ("trimmed c3 by 400 ms at the end", "moved t1 to 2.0 s", "added clip c7 (ast_…)", "shifted c4, c5 by -400 ms") for the run feed and the version list. It takes the parent spec as well as the patch, because a patch holds array indexes and no old values: replaying the patch on the parent is how it finds the ids and the old numbers.
- **Beat snapping (P3-09, `internal/timeline/beats`).** `snap_cuts_to_beats` calls `beats.SnapCuts(cuts, grid, opts)` with `StartMs` 0 and `EndMs` the total duration, on the grid from `Grid.Place({at_ms, source_offset_ms})` so beats are in timeline time. Behaviour the op relies on:
  - A snapped cut sits at `FrameToMs(frame(beat))`: frame-aligned, and less than one frame from the exact beat (at most half a frame plus half a millisecond). The error is reported per cut, so the op can warn on it.
  - A cut that can't be snapped stays exactly where it was (unaligned, since the renderer snaps it anyway) with a reason: `out_of_range` (no beat within the max shift; default half a beat) or `min_shot`. A cut already within one frame of a beat goes to that beat, never to a downbeat.
  - Every shot stays at least 300 ms, or as long as it was if it started shorter. Cuts never cross or merge. When the best beat doesn't fit, the next-best in range is tried. The result is idempotent.
  - `Markers` returns `beat` (strength 0.6) and `downbeat` (1.0) entries, plus `drop` (1.0) for given drop times, frame-aligned the same way, so a marker and a cut on the same beat have the same `at_ms`.
  - **The op moves a cut by a rolling edit**: it trims the end of the clip before the cut and the start of the clip after it (source in/out change, the total length does not). The source ranges are found so that the output durations hit the new cuts exactly where the clip's speed allows (at 0.25x a source millisecond is 4 ms of output, so the cut can be a few ms off the frame); the next clip starts from the end of the previous one as it really is, so rounding never adds up. A cut whose move would take a clip outside its asset (in point below 0, out point past the asset, nothing left to play) stays where it was, like the cuts the beat utilities refuse, and each cut that stays is reported as a `cut_not_snapped` warning. `write_markers` replaces the `beat` and `downbeat` markers (other kinds stay) with the grid's beats on the timeline.

## 5. Text, styles and safe zones (P3-04)

- **Safe zones are per format** (D-25), Go values in `internal/timeline/style` (`style.ZoneFor`, reached from a spec's output by `Output.Zone()`), so the validator and the renderer use the same rectangles. For 9:16 the zone follows [research §3.4](../02-research.md#34-captions-safe-zones-beat-snapping): keep out of the top 240 px, the bottom 660 px and 120 px on each side, and out of the right-hand action column (x > 900 for y > 840). 1:1 and 4:5 keep a 5 % margin on every side; 16:9 keeps a 10 % title-safe margin and the bottom 15 % clear. The zone also has a **text column**: the zone narrowed symmetrically about the vertical centre line so that it keeps out of the blocked area too (9:16: x 180 to 900). Text is wrapped at the column's width, so centred text never meets the action column at any height.
- **One layout for validation and rendering.** `style.Measure` lays a text out in a style (real font advance widths, word wrap, outline and shadow padding) and `timeline.PlaceText` places it: an anchor puts the box's top on the zone's top (`upper_third`), its bottom on the zone's bottom (`lower_third`) or its middle on the middle of the output, moved into the zone if it is tall (`center`); a `position` centres the box on `(x × width, y × height)`. `Validate` checks that box (anchors included, since a very tall text can overflow the zone) against the zone and the blocked area and reports `unsafe_text` at `/position` or `/anchor` with the sizes and the edge that is out. The renderer draws the item at the centre of that same box. If a spec that skipped validation has a box that is not safe, the renderer moves it the shortest way into the zone (`Zone.Fit`), and leaves the item out with a `text_dropped` warning if even that cannot make it safe; a validated spec is never moved. The old 0.6 em estimate is gone.
- **Real widths.** A font's advance widths come from its `hmtx` table and one font unit is `size / (usWinAscent + usWinDescent)` pixels wide, which is how libass scales a font (a line is `size` px tall); both were measured against libass 0.17 renders. No kerning is applied (it only narrows the pairs that matter), and every width is widened by 0.5 % because libass places hinted, rounded advances that run a pixel or two wider than the sum on a long line of wide capitals. The tables are generated from the vendored font files by a minimal sfnt reader (`go generate ./internal/timeline/style`, committed as `metrics_gen.go`; a test regenerates them and fails if they differ from the files). The box includes the style's outline and shadow plus one pixel, so ink inside the box is inside the zone. A test renders every style on every format with ffmpeg and measures the ink against the box, in CI and in the media-tools image.
- **Characters without a glyph (decision).** The layout only knows the glyphs of the style's font, so the validator refuses text with a character that font cannot draw: `unsupported_character` (error, at `/text`), naming the characters. Supported are the characters the generated tables carry for that font (Basic Latin, Latin-1 and Extended, Vietnamese, Cyrillic where the font has it, general punctuation, currency and a few symbols), spaces, newlines and zero-width characters. So an emoji, CJK text or Cyrillic in Anton is an error the agent can fix, instead of a fallback font with an unknown width that would break the safe-zone claim. The renderer drops such characters from anything it still receives (text of a spec that skipped validation, transcript words in captions), and `Measure` keeps one em as the width of a character it does not know as a last line of defence. Supporting more scripts means a font with them, a manifest row and a wider generated range.
- **The style registry** (`style.Lookup`, `style.IDs`) maps a style id to a font, a size, colours, an outline or box and a shadow. **Sizes are ems**: `EmPct` is the em of the font as a percentage of a 1920 px tall 9:16 canvas, scaled by the shorter side of the output (1080 px on all four formats), and the ASS font size is derived as `em × (usWinAscent + usWinDescent) / unitsPerEm`, so Anton, Inter and Montserrat at the same `EmPct` look equally big, and a style is the same size in pixels on every format. Captions are 5 % (96 px), titles 4.6 % (`title_bold`) and 5.5 % (`title_outline`), `stat_big` 11 %, `label_box` 3 %, `subtitle_clean` 2.8 %. Outline and shadow are percentages of the ASS font size. Seven styles: `caption_highlight`, `caption_plain`, `label_box`, `stat_big`, `subtitle_clean`, `title_bold` and `title_outline`. A text item can use any of them; the captions track uses `caption_plain` for `chunk` and `caption_highlight` (the spoken word in yellow) for `word_highlight`. An id the registry does not know is `unknown_style`, an error.
- **Animation default (decision).** An omitted `animation` is `none` everywhere: the schema's default, `TextItem.AnimationOrDefault`, the renderer and this note. Styles carry no default animation (there is no `style_default` value), so what the agent writes is what is drawn.
- **Fonts** are an allow-list of three OFL-1.1 families (Anton Regular, Inter Bold, Montserrat ExtraBold), vendored unmodified in `packages/media-tools/fonts` with their licence texts and `manifest.tsv` (version, source URL and SHA-256 of every file); `scripts/fetch-fonts.sh` downloads them from the official repositories at the pinned versions and checks every hash (`--check` verifies the committed files, in CI). The image copies them to `/usr/share/fonts/cf` and lists each in the licence inventory and allowlist ([D-16](../05-decisions.md#d-16-licensing-policy-for-ml-and-media-components)). The spec cannot name a font.
- **Escaping:** the spec's text and a transcript's words are plain text, never markup. Every text is written into the `.ass` Dialogue line character by character: `{` and `}` become `\{` and `\}` (libass reads those as the characters), a backslash is followed by a word joiner (U+2060, invisible, zero width) so it can never start `\N`, `\h` or a tag, control characters and U+2028/2029 become spaces, and a line break (the layout's own, `\N`) is written only by the renderer. User text never reaches a filter argument. A test renders `{\pos(0,0)}`, `{\fs200\an9}`, `\N` and friends and checks that the ink is as wide as the layout says and inside its box, which it would not be if a tag were read.
- **Rendering:** all text, captions and the preview watermark become one generated `.ass` file per render (`Plan.Subtitles`), burned in with `ass=filename=subs.ass:fontsdir=…` after the clips are joined. The script's PlayRes is the spec's output size in every profile (the preview renders at half size and libass scales the script), WrapStyle is 2 and every event places its text with `\an5\pos` at its box's centre, with its own `\N` line breaks, so libass lays out nothing itself. `Execute` writes the script into the work directory (ffmpeg's working directory in every provider, so it is found by relative name). **Fonts (decision):** when the runner is a sandbox runner over the docker or hardened provider, ffmpeg runs in the media-tools image and the graph reads the image's own `/usr/share/fonts/cf` (`Execute` rewrites `fontsdir=fonts` to it in the arguments it runs; the plan stays the same), so nothing is staged and a render works outside a repository checkout. Only for the local provider, which runs the host's ffmpeg, are the fonts the plan names copied next to the script, from `ExecuteOptions.FontsDir` or `packages/media-tools/fonts` found above the working directory (`cfctl render --fonts-dir`); without them it fails with `ErrNoFonts` and says what to do. `Execute`'s signature did not change.
- **Animations** are ASS tags: `none`; `fade` (`\fad`, 150 ms at most a quarter of the event); `pop_in` (`\fscx60\fscy60` to 100 % over 180 ms with `\t`, plus a short fade; no overshoot, so the box never grows past the validated one); `slide_up` (`\move` from at most 2 % of the height lower, 250 ms, clamped by `Zone.SlideRoom` so it starts inside the zone too, and a plain fade where there is no room); `typewriter` (every character starts transparent and a per-character `\t` switches it on). A character takes at most 45 ms, and the last one starts within 60 % of the event for any text length and duration: a 120-character text on a 300 ms event is typed at 1.5 ms a character, several characters switching on in the same millisecond. Every position an animation passes through is inside the safe zone, and a property test checks it.
- **Event times** are written between two frames. ASS has centisecond times and libass shows an event on `[start, end)` of each frame's timestamp, which ffmpeg versions truncate or round to a millisecond; the writer puts the boundary of frame n half a frame before the frame's own time, rounded to a centisecond, which lies strictly between the timestamps of frames n-1 and n at 24, 25, 30 and 60 fps whichever way they are computed (a test checks 20 000 frames at each rate). An event is therefore on exactly the frames the time map gives it.
- **Captions.** The transcript type is `render.Word{Text, StartMs, EndMs}` per asset (times in the asset), taken through `ResolvedAsset.Transcript`; P2-05 will produce them. For each clip, the words it plays are mapped through the time map: source time `s` is spoken at `out_start + (s - in) / speed`, both ends snapped to frames like every boundary, cut to the clip's in and out points and to the frames the clip's own audio plays: **through a transition too**, so during a crossfade the outgoing clip's words last until its audio ends (frame of its end), even though the incoming clip owns those frames in the time map. A word is at least a frame long, and overlapping speech (also between the two clips of a transition) is resolved by letting the later word start where the earlier one ends. Words become chunks of at most `max_words`, and a chunk also ends at a pause longer than 600 ms, after a word ending in `.`, `!`, `?` or `…`, and at a cut. `uppercase` (default on) uppercases the text before it is measured, and characters the caption font cannot draw are dropped. A `chunk` caption is one event from its first word to its last. A `word_highlight` caption is one event per word with that word in the highlight colour, plus an event for each pause inside the chunk with nothing lit, so the chunk stays on screen and the highlight follows the voice; a word wrapped over two lines is lit on both. Sync is exact (0 frames of error) in the tests, across speed changes, a cut and a crossfade.
- **The caption band, and fitting captions (decision).** Captions are centred at 62 % of the safe zone's height, in a **band**: the zone's text column, two lines of the caption style tall (`style.CaptionBand`). A chunk is laid out and must fit the band; one that does not is split in two and each half tried again, and a single word that is still too big is shrunk to 90, 80 and 70 % of the size, and finally left out with a `caption_dropped` warning in `Plan.Warnings` (`cfctl render` prints it). So a caption is never drawn outside the zone, and the validator checks that the band itself is inside the zone for the format (`unsafe_text` on the captions track otherwise).
- **Text and captions do not collide (decision).** While an enabled captions track exists, a text item whose box overlaps the caption band is `text_overlaps_captions` (error, at its `/anchor` or `/position`): captions can be on screen at any time, and the agent does not know when the speaker speaks. `upper_third` and `lower_third` titles and positions above or below the band are fine; `center` is not. A disabled captions track reserves nothing.
- **The preview watermark** is a small `PREVIEW` in the top right corner of the safe zone (clear of centred titles; the renderer's own style, not in the registry, so the spec cannot use it), on every format, for the whole video. Like everything else it is only drawn if its box is inside the zone.

## 6. Compiler and renderer (P3-03, P3-05, P3-06)

**Pure compile, separate execution.** `render.Compile(spec, profile, resolver) (Plan, error)` returns:
- the ffmpeg argument list,
- the generated ASS text,
- the time map,
- the frame-snapped cut list.

It never runs ffmpeg. `render.Execute(ctx, plan, sandbox)` runs it later, through the media package and the sandbox provider from P1-03. Golden tests can then assert on the plan itself, quickly and without ffmpeg.

**Frame snapping:**
- `frame(ms) = floor(ms × fps / 1000 + 0.5)`.
- Item boundaries are snapped from the cumulative `at_ms`, never from summed durations, so rounding can't drift over a long timeline.
- Item `i` covers frames `[frame(at_i), frame(at_{i+1}))`.

**Video graph per main item:** `trim` on the source frames → `setpts=PTS-STARTPTS` → `setpts=PTS/speed` → `fps` → reframe → look → `format=yuv420p` → `settb`.
- **Reframe `cover`** scales to fill, then crops around `focus` (clamped so the crop stays inside the frame), then applies `zoom` as an extra centred crop and scale.
- **`contain`** pads with `background`.
- **`blur_fill`** places a blurred, scaled copy behind a `contain`.
- **Joining items:** a plain `concat` when every transition is a cut; otherwise an `xfade` chain with offsets from the snapped cut list. `whip` is an `xfade` `slideleft` with a short blur.
- **Looks** are fixed `eq` and `curves` settings per preset. No external LUT files in v1.

**Audio graph:**
- **Source audio** from main items with `use_source`: `atrim` → `asetpts` → `atempo` chained to cover speeds outside 0.5–2 → `volume`.
- **Audio-track items:** `atrim` from `source_offset_ms` → `afade` → `adelay` to `at_ms` → `volume`.
- **Mix and normalise:** everything is mixed with `amix=normalize=0`, then `loudnorm` targets I = −14 LUFS and TP = −1 dBTP. The final profile runs two passes; the preview profile runs a single dynamic pass.
- **Cue-only sounds are never reproduced.** `cue_only` items are dropped from the graph **in every profile**. Compile collects the cue (`trend_id`, `at_ms`, `source_offset_ms`) into `Plan.SoundCues` for the export package instead.
- **The preview beat guide.** The preview profile adds a generated beat guide built from the markers: 30 ms sine clicks at 1 kHz for `beat`, 1.5 kHz for `downbeat` and a longer accent (150 ms at 2 kHz) for `drop`, at −12 dB. It is mixed in **after** `loudnorm`, not before (see "Decisions made in P3-03"). A test compiles a spec with a `cue_only` item under every profile and asserts that its source never appears among the inputs (D-03).

**Profiles:**

| Profile | Size | Source | Video | Audio | Extras |
|---|---|---|---|---|---|
| `preview` | half the format's size (540×960 for 9:16; 540×676 for 4:5, see below) | proxies (`proxy_720.mp4`) | x264 `veryfast`, CRF 28 | AAC 128k | Watermark, beat guide |
| `final` | the format's size | originals | x264 `medium`, CRF 18, `high` profile | AAC 192k, 48 kHz | `+faststart` |

Both profiles write `yuv420p` and add `-map_metadata -1` and `-fflags +bitexact`, so the output is deterministic.

**Outputs of a render (P3-06):**
- **The MP4.**
- **`time_map`:** a JSON array of `{out_start_ms, out_end_ms, item_id, asset_id, source_in_ms, speed}` for main items, plus `{out_start_ms, out_end_ms, item_id}` for text items. A comment at output time `t` resolves to the main item that covers `t`, and to the source time `source_in_ms + (t − out_start_ms) × speed`.
- **The contact sheet:** one frame 100 ms after each cut plus the last frame, tiled 4 across with the output timestamp drawn on each tile, as JPEG. The editor agent checks its own work from this sheet.
- **Progress events:** parsed from `-progress pipe:1`.

**Decisions made in P3-03.** The compiler had to settle these, and later tasks build on them.
- **`Plan` and the argument list.** `Plan.Args` stops before the output path and leaves out the program name and the logging flags; `Plan.OutputArgs(path)` appends `-y` and the path, and `Execute` adds `-hide_banner -nostdin -loglevel error -nostats -progress pipe:1`. `Plan.FilterComplex` is also inside `Args`. The plan carries `Inputs`, `CutList`, `TimeMap`, `SoundCues`, the output size, the frame count and what is pending (`PendingText`, `PendingCaptions`, `PendingWatermark`); P3-04 adds the ASS text and the font directory. Text items compile to nothing until P3-04 (a test asserts that the command is identical with and without a text track), and so does the preview watermark, which needs a font from the style registry.
- **`AssetResolver`.** `Resolve(assetID, variant) (ResolvedAsset{Location, HasAudio}, error)`, where the variant is `proxy` (preview) or `original` (final) and the location is the absolute path of a local file (the sandbox has no network, so the worker stages the asset first; `Execute` refuses anything else with `ErrRemoteInput`). A clip that asks for its source audio and has no audio stream plays silence instead of failing the render. The resolver is asked once per asset, never for a `cue_only` sound.
- **One input per item, with input seeking.** Every main item and every audio item is its own ffmpeg input with `-ss <in> -t <span>`, so ffmpeg seeks instead of decoding a 60 s original up to the clip; the graph still starts every clip with `trim=end=<span>,setpts=PTS-STARTPTS` (and audio with `atrim=end=...`). Every input is opened as an untrusted file, like `internal/media` does: `-protocol_whitelist file -format_whitelist <media.UntrustedFormats>`, so an uploaded playlist cannot make ffmpeg read other files or hosts. The measuring pass of the final profile opens only the inputs whose audio the mix uses.
- **Exact lengths.** After `fps`, every clip goes through `tpad=stop=-1:stop_mode=clone` and `trim=end_frame=<frames>`, so a clip always has exactly the frames its snapped boundaries give it (a source that is a frame short repeats its last frame), and `fps=<n>,settb=AVTB` ends the chain so that `xfade` and `concat` see a constant frame rate.
- **Joins.** All cuts: one `concat`. Otherwise the clips are added one at a time: `concat=n=2` for a cut, `xfade` for a transition, with `offset` = the incoming clip's start frame and `duration` = the overlap in frames, both formatted in microseconds so they land exactly on the frame. A whip is `xfade=slideleft` followed by a `gblur` enabled for the length of the transition, end-exclusive (`gte(t,a)*lt(t,b)`: the first frame after it is not blurred). Compile refuses a spec whose snapped boundaries show a gap, an overlap without a transition, or a transition without an overlap, and one where a transition overlaps as many frames as either clip it joins or where the transitions into and out of a clip together take all of its frames (`timeline.Validate` raises `transition_too_long` for the same specs, checked in frames at the spec's fps, so the two agree; fixture `i47`).
- **Reframe.** `cover` is `scale=…:force_original_aspect_ratio=increase` then `crop` at `clip(focus × size − half, 0, size − crop)`. `zoom` is the extra centred crop of `size / zoom` and a scale back, applied after the mode for all three modes. `contain` pads with `output.background`. `blur_fill` blurs a copy shrunk to a twelfth of the frame (cheap, and as smooth as a large blur) and overlays the contained clip.
- **Looks** are `eq` and `curves`; every preset that uses `curves` (`warm`, `cool`, `matte`) runs in planar RGB (`format=gbrp`) and converts back, so the pixel format does not depend on what an ffmpeg version would negotiate.
- **Sizes.** The profile size is the spec's size divided by the profile's divisor and rounded up to an even number, because `yuv420p` needs even sizes: half of 1080×1350 (4:5) is 540×676, not 540×675.
- **Time map.** An item owns `[start of its first frame, start of the next item's first frame)`: during a transition the overlap belongs to the incoming item, so every output time resolves to exactly one main item. The last item owns up to the end. Text items are `[frame(at_ms), frame(at_ms + duration_ms))`. All times are frame starts in whole milliseconds.
- **Audio.** Every render has an audio stream: the mix starts from a silent bed of exactly the video's length (`anullsrc`), and `amix=duration=first` keeps the length. Source audio of clips that overlap in a transition crosses over with `afade` in and out of the transition length. When nothing but the bed is left (no source audio, no licensed or creator audio) there is no `loudnorm` at all and the plan has no `Loudnorm`. The beat guide is a set of gated `sine` sources (one per kind of marker, a `volume` expression that is evaluated per 1 ms frame): an `aevalsrc` with a term per marker costs seconds on a 30 s timeline. It is mixed in after `loudnorm`, because the guide is a preview aid and not part of the programme: before it, a timeline whose only sound is a `cue_only` cue would have its clicks boosted to −14 LUFS.
- **Two-pass loudnorm.** `Plan.Loudnorm` holds the single-pass filter exactly as it appears in the graph, whether the profile wants two passes, and the arguments of the measuring pass (the audio part of the graph with `print_format=json`). `Execute` runs that pass, reads the JSON from ffmpeg's log, and swaps the filter in a copy of the arguments for `…:measured_I=…:measured_TP=…:measured_LRA=…:measured_thresh=…:offset=…:linear=true`. A measurement below −70 LUFS (silence) keeps the single-pass filter. The plan itself is never modified.
- **Execution through the sandbox.** `Execute(ctx, plan, runner, ExecuteOptions{Output, WorkDir, Progress})` takes a `media.Runner` (`internal/media`): in production a `media.SandboxRunner` over the docker or hardened provider of `internal/sandbox` and the media-tools image, in development the local provider (no isolation). Each distinct input file is mounted read-only at `/in/<n>` and the plan's `-i` locations are rewritten; the one writable mount is a work directory (a fresh temp directory by default, which must be inside the provider's allowed roots) holding the output and the `-progress` file. The sandbox returns a result when the job ends and does not stream, so `Execute` polls the progress file on the host while the job runs (`Progress{Stage, Frame, OutTimeMs, Fraction, Speed, Done}`, stage `measure` or `render`) and moves `out.mp4` to the requested path at the end. A non-zero exit is a `*media.ToolError` with the tail of ffmpeg's log; `sandbox.ErrSandbox` and `ErrTimeout` come back wrapped. `DefaultLimits()` gives a render job 4 CPUs, 4 GiB, 1024 PIDs and 30 minutes. With text, the script is written into the work directory too, and the fonts are the image's own in docker and hardened, staged from the host only for the local provider (section 5). `cfctl render --provider local|docker|hardened` uses the same path.
- **A `Plan` is plain data** and survives JSON, profile included (`Plan.Profile` has JSON tags), so it can be stored with a render and run by another process.

## 7. Tests

**Fixtures (P3-01):** at least 30 valid and 30 invalid specs (31 and 46 today), covering every issue code and every format at least once. `fixtures/expect.json` maps each invalid file to `{code, path?, keyword?}`; the Go tests read it as well and assert that the issue codes raised are exactly the expected one. The valid ones are structurally and semantically valid against `fixtures/assets.json`. Invalid fixtures that expect `schema` must fail the JSON Schema with an error at the expected instance path (and keyword); the ones that expect a semantic code must pass it and are caught by the Go layer. `packages/schemas` tests the first half with Ajv (2020-12, strict mode) and checks that `render.txt` covers every format, transition, reframe mode, look, audio kind and both ends of the speed range; the Go tests check the second half and that the Go types round-trip every valid fixture.

**Golden plans (P3-03, P3-04):** 20 of the valid fixtures are also render fixtures (listed in `fixtures/render.txt`; P3-04 adds five text and caption fixtures in `fixtures/render-text.txt`, so that the P3-01 fixture tests keep their count), covering every format, transition, reframe mode, look, speed range and audio kind). For each of them and each profile, the compiled argument list, the filter graph (a statement to a line), the inputs, the cut list, the time map, the sound cues and the generated ASS script are snapshot-tested as text files under `testdata/golden/plans/<fixture>.<profile>.txt`. They need no ffmpeg, so they run in `go-test` as well. `go test ./internal/render -update` rewrites the snapshots, and a reviewer reads the diff.

**Golden renders (P3-03):**
- **Media:** the test media is generated when the tests run, so no binary fixtures are committed. It's cached in `testdata/.cache` (git-ignored; the cache path carries a version to bump when the generator changes). Every video asset of `fixtures/assets.json` becomes a 640×360, 30 fps clip of the asset's duration, with an audio track, in a colour of its own: high-contrast, soft-edged bars that move 7 px a frame, four coloured corner marks and the **source frame number as seven-segment digits drawn with `drawbox`**, so no font is needed and every ffmpeg draws the same pixels. Audio assets are sine tones. (Hard edges and faint detail score below the threshold across ffmpeg versions; big structure scores well.)
- **Rendering and sampling:** every render fixture is rendered with the `preview` profile, and five with `final` too (a cover with a focus point, a whip, `blur_fill`, an audio mix and the full edit). The test checks the output's size, frame count and audio stream, then compares frames at the first and last frame, the frame before and the first frame after every cut, the middle of every transition, the first frame after a whip (its blur window is end-exclusive) and the middle of every item.
- **Comparison:** each sampled frame is scaled to 108 px wide and compared with the PNG committed under `testdata/golden/frames/<fixture>/<profile>/`, with an SSIM ≥ 0.98 (`go test ./internal/render -update` rewrites them). SSIM is computed in Go (8×8 windows, mean of the R, G and B planes, after a 3×3 average) so it does not depend on the installed ffmpeg; the average keeps the half-pixel differences between ffmpeg versions' scalers out of the score and leaves the structure. The frame-number overlay makes an off-by-one cut fail, and the test proves it can: for every sample in the middle of a clip that plays at normal speed or faster, the next frame must score **below** 0.98 against it (it scores 0.9 at most).
- **Cross-version margin:** the committed frames were made with ffmpeg 7.1 (arm64) and pass with the pinned 8.1 (x86-64) at SSIM 0.988 or better; x264 at CRF 28 differs between builds, which is what the 108 px width and the content design absorb.
- **Audio checks:** the final render of the licensed-track fixture is at −14 LUFS ±1.5 and its true peak at most −0.5 dBTP; a timeline with no sound and the final render of the `cue_only` fixture are digital silence; the preview of the `cue_only` fixture holds the beat guide (−12 dBFS) and nothing else.
- **Where they run:** ffmpeg 8 is pinned in CI (the `render` job) as a static build, because the golden frames need the host's ffmpeg (to generate the media and extract frames) and the media-tools image takes too long to build in that job: the BtbN GPL build n8.1.3 from the `autobuild-2026-09-30-13-08` release, with its SHA-256 checked before it is unpacked. The tests skip, with a clear message, when ffmpeg is missing or older than 7 locally; in CI `CF_RENDER_REQUIRE_FFMPEG=n8.` turns a missing or different ffmpeg into a failure. The `media-tools` job also renders the full edit through the docker provider and the image (`TestIntegrationRenderInDocker`, which generates its own sources and checks size, length and audio, not pixels); when the image is published to a registry the `render` job can pull it and run the golden renders through the sandbox too.

**Text and captions (P3-04).** The acceptance is "text never lands in the unsafe zones; captions stay in sync within 1 frame", and each half has tests that do not depend on a library version:
- **Safe zones.** A property test (`TestPropertyTextIsSafeOrReported`, 600 random texts, anchors or positions, styles, animations and formats) asserts that `Validate` reports `unsafe_text` exactly when the shared layout's box is not safe, that the renderer draws a safe item at the centre of the box the validator measured, and that the start of a `slide_up` is safe. The ink tests render every style on every format and anchor, plus random positions and animation start frames, with ffmpeg and libass onto a flat grey frame and require the ink (everything that differs from the background) to lie inside the layout box and inside the safe zone; the same check runs in the media-tools image (`TestIntegrationTextInDocker`, which CI's `media-tools` job runs with `-docker-image`). The watermark is checked the same way. Mutating the padding to zero fails 140 of these tests.
- **Caption sync.** `TestCaptionSync` maps the fixture transcript through the plan's time map and the spec's clips with its own code, parses the generated script, asks which frame each event first shows on (with timestamps both truncated and rounded to a millisecond) and requires every word's first and last frame to be the expected ones, exactly, for a captions fixture with a speed-up, a slow-down, a cut and a crossfade (`v34`), a word-highlight fixture in 16:9 (`v35`) and the P3-01 captions fixture. `TestEventTimesLandOnTheirFrame` checks the time writer for every frame up to 20 000 at 24, 25, 30 and 60 fps. Test transcripts are generated (a word every 420 ms per asset, starting at a different place for each asset), so no media or ASR is needed.
- **Review round 1 additions.** The typewriter reveals within 60 % of the event at the extremes (120 characters on 300 ms); an omitted animation is `none` in the script; style sizes are ems (the em in pixels is the same for every font at the same `EmPct`); unsupported characters are refused by `Validate` and dropped by the renderer; captions stay in the band (an impossible word is shrunk or dropped with a warning); text over the caption band is refused; the outgoing clip's captions last through a crossfade; `Execute` reads the image's fonts for docker and hardened and stages them for local (fake providers, run outside a checkout). Fixtures `i48` to `i50` raise `unknown_style`, `unsupported_character` and `text_overlaps_captions`; `v1.test.ts` derives the issue codes from `expect.json` and the render fixture lists from `render*.txt`.
- **Escaping.** Unit tests on the script (no unescaped `\`, `{` or `}` can be left in a Dialogue line) and a render test (`{\pos(0,0)}`, `{\fs200\an9}`, `a\Nb`, `x\{\pos(0,0)\}` are drawn literally, with and without the typewriter animation).
- **Golden plans and frames.** The five fixtures of `render-text.txt` and the P3-03 ones (the preview now carries the watermark) have golden plans, with the ASS script, and golden frames. Frames that show text or captions are compared at 216 px wide (the others at 108) and need an SSIM of 0.95 instead of 0.98, because libass rasterises and animates a little differently between versions: the committed frames are made with the host ffmpeg like the P3-03 ones (`go test ./internal/render -update`), and pass with the pinned 8.1 static build in CI and with the media-tools image (`-docker-image media-tools:dev` renders the golden fixtures through it; its text frames score 0.98 or better against them). The text tests above are what pins position and timing exactly.

**Timing (P3-06):** a 30 s edit renders as a preview in ≤ 10 s and as a final in ≤ 60 s, measured on the target host class and reported in the PR. A CI timing test is too noisy to gate on: `go test ./internal/render -run TestRenderTiming -timing -v` logs a 30 s edit (ten clips with crossfades and whips, looks, all three reframe modes, source audio, a licensed track and 60 markers) for both profiles.

## 8. Order and boundaries

P3-01 schema and validation → P3-09 beat utilities → P3-02 ops (including `snap_cuts_to_beats`, which uses P3-09) → P3-03 compiler → P3-04 text and P3-05 audio → P3-06 render jobs (needs River from P0-06 and storage from P1-01) → P3-07 and P3-08 web (need the API from P0-08). P3-07 includes the range-selection timeline under the player and the comment history side panel ([plan, P3-07](../04-implementation-plan.md#p3--timeline-spec-and-renderer--34-weeks-parallel-with-p1p2)).

Effect presets ([D-26](../05-decisions.md#d-26-video-effects-are-presets)) arrive as additive v1 fields: `motion` on video items and new transition types (P3-10), and a `graphics` track whose items reference a template (P4-11).

Out of scope for v1: overlay video tracks, keyframed motion, LUT files, the in-browser live preview and HyperFrames titles. The schema leaves room for them: new track types and new enum values are additive changes inside `v1`. Anything that changes the meaning of an existing field needs `v2`.
