# 06 — Setup and credentials

> Status: **draft v0.1** · 2026-10-16
> What to create, where each value goes and when it is needed, so the implementing agent never has to stop and ask for a key. The variable names live in [`.env.example`](../.env.example), the single source of truth. Markers: ◐ read in the vendor's own docs while researching; △ from memory or a secondary source, so check it when you create the resource.

## 1. The short version

- **To start you need three values:** an Anthropic key for a `dev` workspace, and the publishable and secret keys of a Clerk development instance. Everything else a local setup needs has a default (Postgres in Docker, MinIO standing in for R2) or is generated by the agent.
- Copy `.env.example` to `.env`, fill the three `[YOU-now]` lines and run the check in [§6](#6-checking-it).
- **Cloudflare, servers, observability and the rest wait for staging** (P0-09 and P0-10, about week 2). Create them then, or all at once if you prefer. Each `[YOU-...]` tag in `.env.example` says when.
- **Where values live.** Local values go in `.env`. Staging and production values go in `.env.staging` and `.env.production` on your machine (gitignored by `.env.*`) and in the GitHub environment secrets. Nothing secret goes in git, in a chat message, or in a `VITE_` variable, because those ship to the browser.
- The agent runs on your machine, so it reads `.env` directly and can use your logged-in tools (Docker, `wrangler`, `gh`).

## 3. Services

### 3.1 Anthropic

Create four workspaces in the Console, one key each. Each has a monthly spend limit that sits behind our own budgets as the last backstop ([D-18](05-decisions.md#d-18-who-pays-for-tokens-managed-credits-or-bring-your-own-key)).

| Workspace | Used by | Limit per month | Key goes to |
|---|---|---|---|
| `dev` | local development and benchmarks | $50, raised for a paid sweep ([D-22](05-decisions.md#d-22-cheap-first-testing-ladder)) | `ANTHROPIC_API_KEY` in `.env` |
| `ci` | GitHub Actions model tests | $25 | the CI secret `ANTHROPIC_API_KEY` |
| `staging` | the staging app | $100 | `.env.staging` |
| `production` | the production app, managed credits | $500 (the private beta is capped at about $375 a month) | `.env.production` |

- Only `dev` is needed to start. Create the others when staging and CI exist.
- Creators' own keys (BYOK) are never in `.env`. They sit encrypted in Postgres under `SECRETS_MASTER_KEY` ([architecture §11a](03-architecture.md#11a-model-access-managed-credits-or-byok)).
- `ROUTING_PROFILE` starts at `dev-cheap` and `LLM_MODE` at `live` ([D-22](05-decisions.md#d-22-cheap-first-testing-ladder)).
- `ANTHROPIC_BASE_URL` stays empty except in staging and production, where it is the gateway URL ([§3.3](#33-cloudflare-needed-from-p0-09)).

### 3.2 Clerk

1. Create an application and turn on **Organizations**, because they are our workspaces.
2. Use the **development instance** for local work and staging. Copy the publishable key (`pk_test_…`) into `VITE_CLERK_PUBLISHABLE_KEY` and the secret key (`sk_test_…`) into `CLERK_SECRET_KEY`. The TanStack Start SDK reads exactly these two names ◐ (`@clerk/tanstack-react-start`).
3. `CLERK_ISSUER`, the Frontend API URL, is derived from the publishable key by `task env:init`, or you copy it from the dashboard under API keys △. `CLERK_JWKS_URL` defaults to `<issuer>/.well-known/jwks.json` △. The Go middleware verifies session JWTs against them.
4. **Webhook, on staging.** Add an endpoint `https://<staging api host>/v1/webhooks/clerk` for the `user.*`, `organization.*` and `organizationMembership.*` events, and copy its signing secret (`whsec_…`) into `CLERK_WEBHOOK_SECRET`. Locally the handler is tested with signed fixtures, so no tunnel is needed.
5. **Production instance, later.** It needs the production domain and DNS records, and gives `pk_live_…` and `sk_live_…` keys.

### 3.3 Cloudflare (needed from P0-09)

Plan: **Workers Paid**, about $5 a month. The Sandbox SDK needs it ◐, and R2 requires a payment method before it issues API tokens ◐.

The agent creates the resources below with `cfctl bootstrap cloudflare` (P0-15) from the bootstrap token. `{env}` is `staging` or `production`. Local development uses MinIO and no Workers.

| Resource | Name | Notes |
|---|---|---|
| R2 buckets, **EU jurisdiction** | `cf-media-staging`, `cf-media-production` | The jurisdiction is fixed at creation. An EU bucket is reachable only through `https://<ACCOUNT_ID>.eu.r2.cloudflarestorage.com`, so the S3 client must use it ◐. CORS: allow `PUT`, `GET` and `HEAD` from the app origins and expose `ETag`. Lifecycle: abort incomplete multipart uploads after 1 day. |
| Worker: web app | `cf-web-{env}` | TanStack Start deploys as a Worker through `@cloudflare/vite-plugin` and a `wrangler.jsonc` with `main: @tanstack/react-start/server-entry` and `nodejs_compat` ◐. |
| Worker: sandbox gateway | `cf-sandbox-gateway-{env}` | A Durable Object that starts a container. `wrangler dev` runs it in Docker ◐. |
| AI Gateways | `cf-staging`, `cf-production` | Settings from [D-19](05-decisions.md#d-19-model-gateway-cloudflare-ai-gateway-in-byok-mode-openrouter-optional): **Authenticated Gateway on**, **Require provider credentials on**, caching off, payload logging off, **no stored provider keys** (see the note below). Only the gateway id `default` is created automatically, so these are created explicitly ◐. |
| Tunnels | `cf-api-staging`, `cf-api-production` | The Go API on the EU servers is reachable only through its tunnel. The token goes to the server as `CLOUDFLARE_TUNNEL_TOKEN`. |
| DNS records | `app`, `api`, `staging-app`, `staging-api` | Proxied, on your domain. |

**Not used, on purpose.** Cloudflare Pages (the web app is a Worker serving its own static assets), Workers KV, D1, Queues, Stream and Images. State lives in Postgres and R2 ([D-01](05-decisions.md#d-01-database-postgres-from-day-one-skip-d1-for-the-go-backend), [D-04](05-decisions.md#d-04-job-orchestration-river-on-postgres), [D-06](05-decisions.md#d-06-video-delivery-mp4-proxies-on-r2-no-cloudflare-stream-in-v1)). If a Worker later needs a cache, the bootstrap token can create a KV namespace with `wrangler kv namespace create <NAME>` ◐, so nothing needs preparing now.

Tokens. The first is yours to create, and the agent can mint the other two from it.

| Token | Variable | Permissions | Lives in |
|---|---|---|---|
| **Bootstrap and deploy** | `CLOUDFLARE_API_TOKEN` | Account: Workers Scripts Edit, Workers KV Storage Edit, Workers R2 Storage Edit, AI Gateway Read and Edit, Cloudflare Tunnel Edit, Account Settings Read. Zone (your domain only): DNS Edit, Zone Read, Workers Routes Edit. Optional: API Tokens Edit, so the agent can mint the two below. Set an expiry. △ The token builder may word the names slightly differently, so pick the Edit permission of the same product. The two AI Gateway names are ◐. | `.env` and `.env.staging` on your machine, and the CI deploy secret. Never on a server |
| **R2 S3 credentials**, one per bucket | `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | R2 → Manage API tokens → Create Account API token → **Object Read & Write**, scoped to that bucket ◐. The secret is shown once. The agent can mint them instead: the access key id is the token's `id` and the secret is the SHA-256 of the token's `value` ◐. | the server's env file |
| **AI Gateway token**, one per gateway | `CF_AIG_TOKEN` | Gateway → Settings → **Create authentication token** (Run permission), then switch Authenticated Gateway on ◐. It is sent as the `cf-aig-authorization` header ◐. | staging and production only |

> **Security note.** AI Gateway tokens are account-scoped: any token with the Run permission can send requests through every gateway in the account, including ones with stored provider keys ◐. So provider keys are never stored in the gateway. Our own secret store holds them and each request carries the key ([D-19](05-decisions.md#d-19-model-gateway-cloudflare-ai-gateway-in-byok-mode-openrouter-optional)). Treat `CF_AIG_TOKEN` as sensitive in every environment. If that ever matters, move production to its own Cloudflare account.

### 3.4 Postgres

- **Local:** docker compose with the image `pgvector/pgvector:pg17` △ and the `POSTGRES_*` values. Nothing to create.
- **Staging and production:** PlanetScale Postgres. Create one database and one role per environment in an EU region (the research couldn't confirm EU regions, so check when you create it). Copy the **pooled** and **direct** connection strings from the dashboard into `DATABASE_URL` and `DATABASE_DIRECT_URL` △. Request traffic uses the pooled URL. Migrations and the SSE broker's `LISTEN/NOTIFY` use the direct one, because transaction-mode poolers don't support `LISTEN`.
- Cost: from $5 a month per database ([D-01](05-decisions.md#d-01-database-postgres-from-day-one-skip-d1-for-the-go-backend)).

### 3.5 Servers, CI and GitHub

- **EU servers** ([D-09](05-decisions.md#d-09-hosting)). You order one for staging and one for production and create an SSH user with Docker access. The agent installs Docker and `cloudflared` over SSH. The research priced a Hetzner AX102 at about $115 a month for production. Staging is a smaller box and wasn't priced. Values: `DEPLOY_HOST`, `DEPLOY_SSH_USER` and `DEPLOY_SSH_PRIVATE_KEY` (a new key pair made for deploys).
- **GitHub** → Settings → Environments: create `staging` and `production`, with a required reviewer on `production`. Secrets per environment: the `ci` Anthropic key (as `ANTHROPIC_API_KEY`), `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and the `DEPLOY_*` values. Images go to GitHub Container Registry with the built-in `GITHUB_TOKEN`, so they need no extra secret.
- **Renovate:** install the Renovate GitHub App on the repository (P0-03).

### 3.6 Observability

- **Axiom** (the default, [architecture §12](03-architecture.md#12-deployment-environments-observability)): a dataset per environment and an ingest token. `OTEL_EXPORTER_OTLP_ENDPOINT=https://api.axiom.co` and `OTEL_EXPORTER_OTLP_HEADERS=Authorization=Bearer <token>,X-Axiom-Dataset=<dataset>` △.
- **Sentry:** two projects, one for the Go service and one for the web app. Their DSNs go in `SENTRY_DSN` and `VITE_SENTRY_DSN`. A DSN is public by design.
- Grafana Cloud is the open alternative. If you choose it, only these four variables change.

### 3.7 Generated for you

`task env:init` (P0-14) creates the `[AUTO]` secrets. They are different for every environment.

| Variable | Generated with |

## 6. Checking it

**Quick check**, before `cfctl` exists. Fill in `.env`, then run:

```bash
set -a; . ./.env; set +a
for v in $(grep -E '^[A-Z][A-Z0-9_]*=.*\[YOU-now\]' .env.example | cut -d= -f1); do
  [ -n "${!v}" ] || echo "missing: $v"
done
```

It prints nothing when the three start values are present.

**`cfctl doctor --env <local|ci|bench|staging|production> [--phase P4]`** (P0-14):

- The required variables follow the tags: `[YOU-now]` and `[AUTO]` always, `[YOU-staging]` for `staging` and `production`, and the later tags once `--phase` reaches them.
- It makes one cheap authenticated call per service and never prints a value, only the variable name and ok, missing, invalid or skipped. The exit code is 1 on any missing or invalid.

| Service | Call |
|---|---|
| Postgres | `SELECT 1` on both URLs, and a `LISTEN` on the direct one |
| Object storage | put, get and delete a one-byte object with the credentials against `R2_ENDPOINT`, which proves the EU endpoint and signing |
| Cloudflare token | the token-verify call, then list the EU R2 buckets and the AI Gateways △ |
| Anthropic | a token-count request on the configured model, with no generation cost |
| AI Gateway (staging, production) | the same request through `ANTHROPIC_BASE_URL` with `cf-aig-authorization` |
| Clerk | fetch the JWKS, and make one Backend API call with `CLERK_SECRET_KEY` |
| Sandbox gateway | `GET /healthz` on the Worker, with the token |
| Observability | send one test event and expect a 2xx |
| TikTok, billing | format checks only until their phase |

**`cfctl bootstrap cloudflare --env <staging|production>`** (P0-15) is idempotent. It creates the EU R2 bucket with CORS and the lifecycle rule, the AI Gateway with the D-19 settings, the tunnel and the DNS records. It then prints which values to add to `.env.<env>`. It never prints the token, and running it twice changes nothing.

## 8. Every variable by tag

The same tags as in [`.env.example`](../.env.example), which holds the defaults and a comment per line.

- **You provide before the agent starts, `[YOU-now]` (3):** `ANTHROPIC_API_KEY`, `VITE_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`.
- **Local defaults or generated, `[AUTO]` (24):** `CF_ENV`, `APP_BASE_URL`, `API_BASE_URL`, `VITE_API_BASE_URL`, `ROUTING_PROFILE`, `LLM_MODE`, `ANTHROPIC_BASE_URL`, `DATABASE_URL`, `DATABASE_DIRECT_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_JURISDICTION`, `CLERK_ISSUER`, `CLERK_JWKS_URL`, `SECRETS_MASTER_KEY`, `SECRETS_MASTER_KEY_VERSION`, `SANDBOX_GATEWAY_URL`, `SANDBOX_GATEWAY_TOKEN`, `RIVER_UI_PASSWORD`.
- **You provide when staging is set up, `[YOU-staging]` (14):** `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ZONE_ID`, `CLOUDFLARE_TUNNEL_TOKEN`, `CF_AIG_GATEWAY_ID`, `CF_AIG_TOKEN`, `CLERK_WEBHOOK_SECRET`, `DEPLOY_HOST`, `DEPLOY_SSH_USER`, `DEPLOY_SSH_PRIVATE_KEY`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`, `SENTRY_DSN`, `VITE_SENTRY_DSN`.

- **Billing, `[YOU-P7]` (8):** `BILLING_PROVIDER`, `PADDLE_API_KEY`, `PADDLE_WEBHOOK_SECRET`, `PADDLE_CLIENT_TOKEN`, `PADDLE_ENVIRONMENT`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PUBLISHABLE_KEY`. Fill in one provider's set.
